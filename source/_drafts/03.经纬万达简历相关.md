## 数字网格项目

### 隐患排查
#### 侧重业务
- 设计并实现隐患全生命周期状态机（待整改 / 超时待整改 / 已整改待确认 / 已确认 / 撤回 / 驳回 共 8 种状态），覆盖从提交、整改、确认到驳回复核的完整闭环；
- 基于 XXL-Job 实现超时自动判定定时任务，批量扫描超过整改时限的待整改记录并自动流转状态，保障超时逻辑的准确性与时效性；
- 使用 MyBatis-Plus LambdaQueryWrapper 构建多条件动态查询，配合批量查询优化（一次 selectByIds 填充关联用户名），避免 N+1 问题；
- 基于 Spring Cloud Gateway + Nacos 实现微服务网关路由与统一鉴权，JWT 令牌校验 + 白名单放行机制。

#### 侧重「性能 & 质量」
- 负责隐患模块后端核心逻辑开发，包括隐患提交、整改、确认、撤回、驳回及超时自动流转；
- 针对列表查询中的 N+1 问题，采用批量 ID 查询 + HashMap 映射的方式将用户名称一次性填充，查询次数从 O(n) 降为 O(1)；
- 设计「待整改 → 超时待整改」的定时批量处理机制，单次 SQL 更新完成状态流转，避免逐条查询更新；
- 全局统一异常处理，规范返回 {code, msg} 错误码，前端可统一解析。

#### 技术点

根据代码来看，这个模块涉及：

| 技术点 | 具体内容 |
|--------|---------|
| **微服务架构** | Spring Cloud Gateway + Nacos 注册/配置中心，多模块拆分 |
| **定时任务** | XXL-Job 批量处理超时状态流转 |
| **状态机设计** | 8 种状态（待整改→超时待整改→超时已整改→已整改待确认→已确认/驳回/撤回） |
| **批量查询优化** | 先查列表，再一次性 `selectByIds` 批量填充用户名，避免 N+1 |
| **BCrypt 加密** | Spring Security 密码加密 |
| **MyBatis-Plus** | LambdaQueryWrapper 条件构造、分页、动态 SQL |
| **接口鉴权** | Gateway 全局 AuthFilter + JWT Token 校验 + 白名单机制 |
| **异常处理** | 全局统一异常拦截，返回规范错误码 |

#### 三、面试时怎么讲（STAR 法则）

面试官如果追问，按这个结构讲：

| 环节 | 怎么说 |
|------|--------|
| **S 背景** | 智慧工地项目中，需要对施工现场的安全隐患进行全流程数字化管理 |
| **T 任务** | 我负责隐患模块的后端，包括提交、整改、确认、超时自动流转等核心功能 |
| **A 行动** | 1. 设计了 8 种状态的状态机，覆盖正常流程和超时流程两套路径；2. 用 XXL-Job 做定时扫描，超时自动将"待整改"流转为"超时待整改"；3. 列表查询时发现 N+1 问题，改成批量查用户表一次填充，性能提升明显 |
| **R 结果** | 模块上线后支撑了 XX 个工地的日常巡检，超时判定准确率 100%，列表接口响应时间控制在 XX ms 以内 |

---

> **关键技巧**：面试官最看重的是你"遇到了什么问题 → 怎么解决的"，而不是"用了什么技术"。所以讲的时候重点说 **N+1 优化** 和 **状态机设计**，这两个是你真正动脑子的地方。
