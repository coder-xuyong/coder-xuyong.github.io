LambdaQuery/UpdateWrapper

无论是QueryWrapper还是UpdateWrapper在构造条件的时候都需要写死字段名称，会出现字符串魔法值。这在编程规范中显然是不推荐的。

在软件工程中，“魔法值”（Magic Value） 指的是在代码中直接写死的、具有特定含义的常量数值或字符串，但没有任何常量定义或注释来解释它的用途。
那怎么样才能不写字段名，又能知道字段名呢？

其中一种办法是基于变量的gettter方法结合反射技术。因此我们只要将条件对应的字段的getter方法传递给MybatisPlus，它就能计算出对应的变量名了。而传递方法可以使用JDK8中的方法引用和Lambda表达式。
因此MybatisPlus又提供了一套基于Lambda的Wrapper，包含两个：

  • LambdaQueryWrapper
  • LambdaUpdateWrapper

MybatisPlusInterceptor

一般和springboot的配置类一起使用：

这段代码的作用是：告诉 MyBatis-Plus 启用物理分页功能，并且分页语法要适配 MySQL 数据库。

当你在代码中调用 mapper.selectPage(page, wrapper) 时，这个插件就会自动将原本的普通查询 SQL，改写成带有 LIMIT 分页子句的 SQL，并同时执行一次 COUNT(*) 查询来获取总记录数。

关于逻辑分页和物理分页：

  • 物理分页（本行代码的作用）：插件会拦截即将执行的 SQL，在它发送到数据库之前进行改写。比如，你写的是 select * from user，插件会将其改写为 select * from user LIMIT 0, 10，数据库只返回 10 条数据，内存压力极小。
  • 逻辑分页（内存分页）：如果不加这个插件，selectPage 会退化为 select * from user，一次性把全表几百万数据全部加载到 JVM 内存中，再用 Java 代码截取 10 条，这在高并发下会直接导致内存溢出（OOM）。
